# TXO 週選 × 台指期 漲跌停套利掃描

每個交易日自動抓期交所台指期（TX）與台指選擇權（TXO）日行情，判斷近月台指期是否漲跌停，並檢查週選（偏重深價外）在扣除手續費與交易稅後，是否還有違反無套利邊界的組合。

## 架構

```
期交所 CSV ──► GitHub Actions（後端，排程）──► docs/data/*.json ──► GitHub Pages（前端，純查詢）
                     │
                     └─► archive/ 原始 CSV 封存（.gz，可重算、可回測）
```

| 位置 | 內容 |
|---|---|
| `scanner/taifex.py` | 下載（含重試）、解析、封存期交所 CSV |
| `scanner/market.py` | 近月期貨、漲跌停判斷、選擇權鏈整理、隱含期貨價 |
| `scanner/checks.py` | 套利檢查（以可成交買賣價、扣成本計算） |
| `scanner/pipeline.py` | 單日分析 → `docs/data/daily/<日期>.json` 與 `index.json` |
| `scanner/twse.py` | 證交所加權指數：日 OHLC、前日收盤、盤中即時值 |
| `scanner/spreads.py` | 策略三：零風險／有限風險價差賣方、漲跌停日方向性價差，結算後回填實際損益 |
| `scanner/expiry_sell.py` | 策略二：結算日深價外賣方（零風險／低風險區、事後損益、盤中界線） |

| `.github/workflows/scan.yml` | 排程掃描＋提交資料＋部署 Pages |

## 檢查項目

| 檢查 | 期貨腳 | 意義 |
|---|---|---|
| Conversion / Reversal | 小台（每點 50 元，與 TXO 1:1），用該序列對應的小台月／週契約 | C − P 對 F − K 的偏離。漲停時只有「賣期貨」成交得到，跌停反之；非同日結算者標為基差 |
| Box Spread | 不用 | 兩履約價合成多空，到期必收 K2 − K1 |
| 單調性 / 價差寬度 | 不用 | 高履約 Call 不該比低履約貴；價差權利金不該大於間距 |
| 蝴蝶凸性 | 不用 | 1-2-1 蝴蝶到期報酬 ≥ 0，若能淨收權利金即套利 |
| 跨週別 | 不用 | 同時段相鄰兩結算日：近週不應比「價外程度相同」的遠週貴（履約價依兩序列隱含期貨價換算）。違反時賣近買遠；有殘餘風險，歸為「跨週別」 |
| 隱含期貨價 | — | 期貨價 ±5% 內、Call 與 Put 報價都夠緊的履約價 K + C − P 中位數（至少 3 檔，否則不算）；漲跌停時可看出期貨鎖住後的真實價位 |

### 報價可靠性

收盤最佳買賣價是收盤當下仍在簿上的委託，但可能只是零星單筆掛單。任一腳符合以下情況，訊號標為「存疑」：

- 當日無成交且無未平倉
- 買賣價差 > MAX(10 點, 中價 × 30%)（多半不是造市報價）
- 期貨腳當日成交 < 50 口

存疑訊號預設隱藏、不通知、不計入「可成交套利」統計；前端取消勾選「隱藏存疑報價」即可看到，報價欄滑鼠移上去會顯示原因。

## 策略二：結算日深價外賣方

週選結算價＝結算日 13:00–13:30 加權指數平均，而成分股單日漲跌幅 ±10%，所以**結算價必落在「前日收盤 ×0.9 ～ ×1.1」之內**。

| 區域 | 條件 | 風險 |
|---|---|---|
| 零風險 | Call 履約價 > 前日收盤 ×1.1×1.002；Put 履約價 < 前日收盤 ×0.9×0.998 | 到期必歸零。每個結算日都存在，與漲跌停無關 |
| 低風險 | 指數漲停（≥9.5%，可調）時 Put 履約價 ≤ 前日收盤；跌停時 Call 履約價 ≥ 前日收盤 | 指數須把當天漲跌幅全部吐回才會價內；30 分鐘均價會鈍化尾盤急殺 |

- **收盤後（事後驗證）**：結算日排程會抓證交所加權指數，列出兩區當天實際成交價、成交量，以最後結算價計算「賣出損益（扣手續費＋稅）」
- **盤中（可交易）**：週三、週五 09:30／11:00／12:15 抓即時加權指數，寫入 `docs/data/live.json`；接近或達漲跌停時發 Telegram，附可賣的履約價界線。盤中選擇權報價不在本工具內，需自行看報價確認買價 > 約 0.4 點成本
- 0.2% 緩衝涵蓋上市前 5 日無漲跌幅新股等例外；賣方需保證金，極端行情保證金調升仍可能被追繳
- 最後結算價由當日到期序列的結算價反推（價內 Call 的 K＋結算價）；若各檔不一致或超出理論區間會示警

## 策略三：風險可控的價差

**關鍵性質**：從今天收盤到結算還有 n 個交易時段時，結算價必在「今日加權指數收盤 × 0.9ⁿ ～ × 1.1ⁿ」（再外推 0.2%）之內。
n 取到結算日為止的平日數，遇假日只會更窄，所以上下限一定成立。區間內任何價差的最大虧損都能精確算出（已含結算時價內腳的手續費與稅）。

| 策略 | 條件 | 風險 |
|---|---|---|
| 零風險價差賣方 | 賣出點在區間外，再買更外一檔保護 | 到期必歸零；保證金從裸賣 B 值（9.4 萬）降到「價差寬度 × 50 − 權利金」 |
| 有限風險價差賣方 | 賣出點在區間內、距指數收盤至少 3%，保護點更外 | 最大虧損＝區間內最壞情況，事前已知 |
| 漲跌停日方向性價差 | 期貨鎖漲（跌）停或盤中觸及時，順勢買多頭買權（空頭賣權）價差 | 最大虧損＝付出的權利金；方向性交易，不是套利 |

- 價差賣方只做距結算 ≤ 2 個交易時段的序列（結算前一日收盤進場為主）；方向性 ≤ 5 個時段
- 報價用今日一般時段收盤最佳買賣價，訊號於收盤後產生，可於當晚夜盤或結算日早上參考（實際報價會變動，但上下限不變）
- 每組附「歷史虧損機率」「歷史平均損益」：以進場日之前的指數實際 n 時段漲跌幅分布估計（不偷看未來）；有限風險依「每萬元平均損益」排序
- 結算日跑完後，自動以最後結算價回填之前訊號的**實際損益**；網頁「價差策略」頁籤有累積績效
- 回測需要每日加權指數：`rebuild`／`backfill` 會先用 Yahoo 一次補齊到 `archive/taiex/days.json`

## 結算規則（期交所契約規格）

| 項目 | 月選 / 台指期 TX | 週三週選 | 週五週選 |
|---|---|---|---|
| 結算標的 | 加權指數 TAIEX | 加權指數 TAIEX | 加權指數 TAIEX |
| 結算日 | 第 3 個週三 | 第 1、2、4、5 個週三（W1/W2/W4/W5） | 每個週五（F1–F5） |
| 最後結算價 | 到期日 13:00–13:30 加權指數簡單算術平均 | 同左 | 同左 |
| 到期日交易 | 一般時段至 13:30，無盤後 | 同左 | 同左 |

- 每月第一個週三不加掛新週選（次二週即為月選結算日），所以沒有 W3
- 結算標的是**指數不是期貨**；只有 TX 與月選在同一天、用同一個 30 分鐘均價結算
- 序列在自己的結算日 13:30 就已結算，當天收盤後的掃描不再對它出訊號

## 選擇權序列 ↔ 期貨的對應

期貨腳一律用**小台 MTX**（每點 50 元，與 TXO 1:1）。台指期 TX 只有月契約，但小台另有**週三到期的週契約**，
與週三週選同日、同價（30 分鐘均價）結算。每個選擇權序列依期交所「契約到期日」，對到「結算日 ≥ 自己」最近的那口小台：

| 序列（以 2026/11/10 為例） | 結算日 | 對應小台 | 性質 |
|---|---|---|---|
| 202611W2 週三週選 | 11/11 | 202611W2（11/11） | **同日結算 → 真套利** |
| 202611F2 週五週選 | 11/13 | 202611（11/18） | 基差：差 5 天 |
| 202611 月選 | 11/18 | 202611（11/18） | **同日結算 → 真套利** |
| 202611F3 週五週選 | 11/20 | 202611W4（11/25） | 基差：差 5 天 |

小台資料取不到時退回 TX 月契約。

期貨腳一律用**收盤最後最佳買賣價**：買進用賣價、賣出用買價。小台週契約成交稀少，「最後成交價」可能是數小時前的舊價
（例：2026/11/3 小台 W2 僅成交 9 口，最後成交 45080，收盤買賣價卻是 43202／43223）。鎖漲跌停、只剩單邊報價時，以鎖住的價格計算並標為「需排隊」。
漲跌停狀態一律採同時段近月台指期（全市場事件），避免週契約失真的收盤價誤判。成交量低於 50 口的期貨腳會加註「報價可能不穩」。

- 只有同日結算（同一個 30 分鐘均價）的期貨平價訊號才算「無風險套利」，其餘標為「基差」，預設隱藏
- Box、垂直、蝴蝶只用同一序列的選擇權，不受期貨對應影響，任何序列都算套利
- 漲跌停判斷用該序列「對應的那口期貨」的狀態；深價外分界也用那口期貨的價格
- CSV 沒有到期日欄時，由代碼推算：月份＝第三個週三、`W2`＝第 2 個週三、`F2`＝第 2 個週五（不含假日順延）

## 手續費與稅

預設選擇權、小台每口**單邊 35 元**（`scanner/config.py` 的 `opt_fee`、`fut_fee`）。持有到結算時照最壞情況計算：

| 時點 | 選擇權 | 小台 |
|---|---|---|
| 開倉 | 手續費＋權利金 × 0.1% | 手續費＋契約價值 × 十萬分之二 |
| 結算 | 價內：手續費＋結算價 × 十萬分之二；價外歸零：不收 | 手續費＋契約價值 × 十萬分之二 |

事前不知道哪幾腳會價內，所以策略一取「最多可能價內的口數」：Conversion／Reversal 1 口、Box 2 口、垂直 2 口、蝴蝶 4 口、跨週別 2 口（近週結算＋遠週平倉）。
策略二賣深價外：價外歸零只付開倉成本，價內才加計結算成本。

網頁右上角可輸入自己的手續費（最低 10 元），訊號與策略二損益會即時重算；後端另外保存「手續費降到 10 元才達門檻」的訊號供此用。歷史紀錄的統計數字以預設手續費計算。

## 保證金與報酬

每個訊號附「所需資金」與「每萬元賺」「年化%」（持有到選擇權結算）。依期交所規則簡化估算，數值放在 `scanner/config.py`：

| 項目 | 原始保證金（2026/08/12） | 用法 |
|---|---|---|
| 小台 MTX（含週契約） | 175,250 | 期貨腳 |
| TXO A 值 / B 值 | 187,000 / 94,000 | 賣方：MAX(A − 價外值, B)（收到的權利金已入帳） |
| 貸方價差 | 履約價差 × 50 − 收到的權利金 | 垂直、Box 賣方、蝴蝶的貸方那組 |
| 借方價差 | 只付權利金 | 單調性違反、Box 買方 |

期交所調整保證金時改 config（或 workflow env 覆寫 `MTX_MARGIN`、`TXO_A`、`TXO_B`）。實際以期貨商計收為準。

## 漲跌停判斷

- 台指期／小台：收盤鎖住、盤中觸及、收盤接近（±7%）之外，新增「盤中接近」：收盤回落但盤中高／低點曾達 ±7%
- 加權指數（策略二）：同樣納入盤中高低點；低風險區只要當天盤中曾達門檻就成立，大漲、大跌兩邊可同時成立
  （例：2026/11/6 盤中 −8.99%、收盤 −4.51%，會開啟 Call 履約價 ≥ 前日收盤的低風險區）

## 回測結果（2025/4/1 ～ 2026/11/10，393 個交易日）

**策略一（期貨漲跌停時的期貨平價）**
- 期間台指期真正鎖住的只有 2 天：2025/4/7 跌停、2025/4/10 漲停
- 4/7 日盤：期貨鎖 19,167，選擇權隱含約 18,010（低 1,157 點）；Reversal 看似獲利數百點，但跌停賣不出期貨 → 全部「需排隊」。當晚夜盤解鎖後出現 5 筆可成交同日結算 Conversion，最大 83 點
- 4/10：期貨鎖 18,902，選擇權隱含約 19,613（高 711 點）；Conversion 同樣買不到期貨，可成交的只有 Call 蝴蝶錯價 4～8 點
- 全期間可成交、同日結算的無風險訊號 75 筆：報價可靠 52 筆（33 天）、存疑 23 筆；多出現在夜盤
- 4/7 夜盤那 5 筆 Conversion（最大 83 點）都因某腳買賣價差過寬列為存疑，崩盤當晚的報價本來就不穩
- 跨週別：報價可靠的前提下，393 天內沒有出現違反
- 依手續費（單邊）重算可成交、可靠、無風險套利：35 元 20 筆／14 天；20 元 28 筆／17 天；10 元 40 筆／24 天
- 策略二零風險區「賣得掉還賺」的檔次：35 元 21 檔（9 個結算日）；20 元 56 檔；10 元 272 檔（83 個結算日）

**策略二（結算日深價外賣方）**：見上方策略二說明；零風險區 1,737 檔次從未到期價內，但權利金多為 0.1～0.3 點，損益幾乎由手續費決定。

## 加權指數來源

`TAIEX_SOURCE=auto`（預設）：在 GitHub Actions 上直接用 Yahoo ^TWII（證交所會擋海外主機），本機先試證交所再退回 Yahoo。也可設 `twse` 或 `yahoo` 強制指定。

## 資料量

每日 JSON 只保留最近 30 個交易日的完整選擇權鏈，較舊的只留摘要與訊號；原始 CSV 都在 `archive/`，需要時跑 `mode=rebuild` 重算。

## 排程（台北時間）

- 15:40 抓日盤，17:10 補抓（期交所延遲時）
- 隔日 06:30 抓夜盤（期交所把夜盤歸到下一個交易日）
- 每次都重新下載當日 CSV，所以日盤跑完會蓋掉只有夜盤的版本

## 排程可靠性

GitHub 自帶排程在整點、半點負載高時會延遲甚至被丟棄（2026/11/11 實測：夜盤與結算日盤中排程都沒觸發）。三層保護：

1. 排程避開 :00、:30（改 :07、:13、:17、:37、:47）
2. 每次 `run` 會補跑最近 7 天內漏掉、或只有夜盤沒有日盤的交易日
3. **建議**：用 `cloudflare/` 的 Worker 當主要觸發來源（Cloudflare Cron 準時），GitHub 排程留作備援；兩邊都觸發也沒關係，執行是冪等的

網頁在平日超過 26 小時沒更新會顯示警告。

## 限制

- 報價是收盤「最後最佳買賣價」，屬事後偵測；要實際下單需接盤中即時報價
- 週五週選沒有同日結算的期貨，期貨平價只能當基差參考；週三週選與月選有同日結算的小台
- 選擇權本身也有漲跌幅，單邊鎖住時常只有一側報價
- 賣方腳需保證金，極端行情可能被追繳或砍倉
- GitHub 主機在海外：若期交所擋連線，workflow 會失敗並寄信通知；可改用 self-hosted runner 或在本機跑 `python -m scanner run` 後 push
